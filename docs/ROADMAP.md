# 路线图（骨架待填清单）

本仓库的定位是**引擎骨架**：机制与约定先立住，内容留给用户填。下面按优先级列出"骨架已在、内容待补"与"机制待建"的项。

## P0 · 骨架已在，缺的是内容量

| 项 | 现状 | 待填 |
|---|---|---|
| 示例内容 | 1 个包 / 14 场景 / 5 结局（覆盖五种模式） | 可再补 1~2 条示范线（如纯 hub 调查线），作为文档示例 |
| 本地化表 | i18n 机制完备，`locales` 为空表 | 给 starter 配一套 `en-US` 对照表，验证多语言闭环 |
| 存档迁移 | 机制完备，`migrations` 为空 | 写一条示例迁移（如 `1 → 2` 字段重命名），作为模板 |
| 成就 | 4 条 starter 成就 | 随内容扩充 |
| 叙事账本 | 只声明了 starter 的变量 | 各内容包自带变量时补进 §1 |

## P1 · 机制待建（接口已留好）

| 项 | 说明 | 切入点 |
|---|---|---|
| Web UI 适配器 | 换掉 `console-io`，提供 `web-io` 插件（HTTP + SSE/WebSocket） | 新插件实现 `print/blank/ask/wake`，`cordis.yml` 换 `io` 一行 |
| 内容包管理器 | `dse install <包>` / `dse update`：拉包、校验 manifest、挂进 `cordis.yml` | `lib/registry.mjs` 已有 manifest 与校验 |
| 可视化编辑器 | 基于 `schema/scene.schema.json` 生成表单；图分析出可达性实时提示 | `schema/` + `lib/graph.mjs` |
| 存档云同步 | save 插件已有原子写与校验，加一层远端适配器 | `plugins/save.js` |
| 内容包签名 | 顶部安全须知里的问题：不可信包无法靠 `validate()` 拦 —— 可在 manifest 里加签名校验（**在 import 之前**校验文件，才有效） | `lib/registry.mjs` |
| 沙箱化求值 | `if` / `when` 目前用 `new Function`（不是沙箱） | `plugins/state.js` 的 `check()`，可换成受限表达式解析器 |
| 存档快照/回放 | 记录输入序列 → 可复现重放（对测试与"玩家分享线路"都有用） | 新增插件，订阅 `choice/made` |

## 不做（明确边界）

- **不做内容**：本仓库不收游戏本体内容，内容在各自的仓库里。
- **不做编辑器 UI**：只提供 Schema 与 API，编辑器是另一个项目的事。
- **不做通用游戏引擎**：不碰渲染、物理、场景编辑；只做"文字/叙事"这一层。
